---
name: retro
description: Improve the environment an agent works in, using sessions as evidence. Use when asked for a retrospective.
---

A retro improves the environment an agent works in. Every future run inherits that environment, so a small correction compounds.

The session is evidence, not the subject. It shows how the environment shaped the work: what the instructions, docs, skills, tools, and organization made easy or hard. The environment reaches past the repo, and includes the skills the agent invoked, its global instructions, its integrations, and how the work itself is organized and handed off.

An agent that misbehaves is following a bug in its instructions. It acted on what its environment made likely, so the fix belongs in the environment, including inside a skill that misfired. Agent documents and instructions and repo organization are often the best targets for upgrades.

A retro looks for two kinds of change. Repairs remove the cause of friction that happened. Upgrades make something that already works cheaper, clearer, or more reliable, and need no failure to justify them.

A proposal names the change, the evidence, and the benefit. Order proposals by leverage, not by how badly a session went. Silence is a valid result when nothing clears that bar. The retro returns proposals; the human decides what lands.

Write for the environment in front of you. The bar is the same whether the session produced code, prose, or research.
